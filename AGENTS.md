- Stack: TanStack Start (React 19, file routes in src/routes, server functions), Tailwind CSS 4, Supabase, Vite (vite.config.ts), Nitro for the production server (`npm run build` → `npm start`, Node by default; `NITRO_PRESET` for other hosts). npm is the package manager (package-lock.json).
- Two storage modes, never mixed: signed out → everything lives in this browser's IndexedDB (src/lib/local-db.ts); signed in → everything lives in Supabase as the user (RLS). `useAuth()` (src/hooks/use-auth.ts) gives the `scope` ("local" or the user id); query keys include it, mutations read it with `currentScope()`.
- Data access goes through hooks in src/lib/memories.ts, wishes.ts and trips.ts (React Query). Errors are thrown, never swallowed; the QueryClient in src/router.tsx shows them as toasts.
- Supabase client: src/lib/supabase.ts (config from VITE_SUPABASE_URL / VITE_SUPABASE_PUBLISHABLE_KEY). Database types: src/lib/database.types.ts — update it when the schema changes (`supabase gen types typescript`).
- Schema lives in supabase/migrations (Supabase CLI: `supabase db push`). Tables: `memories` (owner full access; anyone can read rows with is_public), `wishes` (owner only), `trips` (owner only; the whole plan is a jsonb `data` column). Photos: private `photos` bucket under `<user_id>/`, shown via signed URLs (src/lib/photos.ts); public memories' photos are readable through a storage policy. Local photos are data URLs in IndexedDB under `local/…` keys.
- The local examples (src/lib/samples.ts) are added only when the IndexedDB database is first created.
- Backups (src/lib/backup.ts) include photos as data URLs and restore into the current scope; ids are kept (or turned into stable UUIDs in the cloud), so restoring twice updates instead of duplicating. This is also how data moves between Supabase projects.
- Feature switches in src/lib/features.ts (`home`, `planner`, `wishes`). Currently all off for a presentation: hidden sections vanish from menus, `/` redirects to `/diario` (`HOME`), `/planeador` and `/desejos` answer 404, and the map/backup texts don't mention them. Their code and data stay intact.
- Pages under `src/routes/_authenticated/` work in both modes (no login gate); `/auth`, `/reset-password` and `/partilha/$id` are public. Sharing needs the cloud.
- Maps: Leaflet + OpenStreetMap tiles (src/components/MemoryMap.tsx); the SVG world map and globes use d3-geo + world-atlas (src/lib/world.ts). Places are geocoded in the browser with Nominatim (src/lib/geocode.ts).
- AI (src/lib/ai.functions.ts, helpers in ai.server.ts / ai-text.ts): story writing and itinerary suggestions. Paid keys (GEMINI_API_KEY, OPENAI_API_KEY, GROQ_API_KEY; optional *_MODEL) are used only for signed-in users in production (any user in dev); otherwise the free Pollinations service is tried (text only), then a plain template. The UI always says when a template was used. Photos are sent as small client-made JPEG thumbnails, never as URLs. src/start.ts attaches the user's token to server function calls.
- Trip dates are ISO `start_date`/`end_date` (old free-text `dates` is shown only when they're empty); reservation times are ISO date-times; formatting, countdown and trip order live in src/lib/dates.ts.
- UI text is European Portuguese and addresses the person as "tu"; headings use sentence case. Use `plural()` from src/lib/utils.ts for counts.
- Colours: calm palette in src/styles.css tokens (dusty blue `primary`, soft greens `sage`/`forest`, `mist`, cool greys). Use tokens or blue/teal/sky/slate Tailwind shades; avoid warm colours except the amber budget warning. White text never goes on `sage` (too little contrast) — use `forest`.
- Exchange rates in src/lib/currency.ts are fixed approximations, labelled as such in the UI.
- The app is installable via public/manifest.webmanifest only (no service worker / offline).
- Hosting: Vercel project `memorias` → https://memorias-tau.vercel.app (Supabase auth site_url points there; localhost:8080 stays allowed). Every push to `main` on GitHub deploys to production automatically, so keep `main` working. Deploy by hand: `NITRO_PRESET=vercel npm run build` then `npx vercel deploy --prebuilt --prod`. Production env vars live in Vercel (VITE_SUPABASE_*, GEMINI_API_KEY).
- Checks: `npm test`, `npm run lint`, `npx tsc --noEmit`, `npm run build`.
